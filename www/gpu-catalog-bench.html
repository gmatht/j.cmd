The GPU-lift catalog: algorithms moved to the fragment / vertex shaders

The fuzzy matcher's recipe (one shader invocation per work item, integer-compute body, data via the texture-window lift or the attribute bridges, result through the RGBA byte buffer) generalises. Pick an algorithm and run it on your GPU — every result is PASS-checked against the exact CPU reference:

  • collatz (fragment) — the Collatz step count per number; one pixel per input, a data-driven loop (each pixel runs its own iteration count), data via the texture window.
  • ca1d (fragment) — one 1D cellular-automaton step (rule 118); one pixel per cell; each fragment reads its THREE neighbours by reassigning the window index between reads.
  • hash (vertex) — a per-record hash; one vertex per record; the record arrives through the attribute bridges (ap_*), the payload leaves through vc_* (×1000 → exact byte round-trip), and the POINTS raster reads back like any canvas.
