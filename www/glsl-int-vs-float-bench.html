GLSL ES 1.00 — int vs float math benchmark (fragment & vertex)

The mimecroft game's fragment shader does its colour math in mediump int (0..127 scale — every intermediate fits mediump int's ±215); its vertex shader is highp float (mandatory). This page times int vs float arithmetic in both stages on your browser's WebGL 1.0 implementation — the same per-pixel workload twice in the fragment, the same per-vertex transform twice in the vertex. The GL/GLSL/ANGLE line below the results identifies exactly which GLES→backend translator your browser is using, so the numbers are read in that context.

How to read this: the GL_VERSION / GLSL_VERSION lines say the API surface (always GLES 2.0 / GLSL ES 1.00 here — the benchmark requires nothing else). The UNMASKED_RENDERER string names the real driver behind the masking (ANGLE on Chromium/Edge/Electron; the native GL on Firefox/Safari; ANGLE → Metal on macOS, ANGLE → D3D11 on Windows, ANGLE → Vulkan on newer builds). The int-vs-float ratio you measure is that translator's lowering of the GLSL ES int/float ALU to the backend's shader language — so the same shaders can rank differently between a D3D11 Intel build, a Metal M-series build, and a Mali phone.

What the GLSL ES 1.00 rules actually force (so the comparison is meaningful)

  • Precision qualifiers are mandatory. The vertex must declare precision highp float;; the fragment defaults to mediump. The benchmark uses the game's exact declarations — mediump int / mediump float in the fragment, highp for the UV/colour varyings (so the texture coordinates don't quantise).
  • mediump int is ±215. The game's intermediates (r·tex_r ≤ 127·255 = 32385, the mix ≤ 127, the hash ≤ 96) fit — the benchmark reproduces them exactly, so the int path is legal on every ES 1.00 device.
  • mediump float has a ~10-bit mantissa — but on desktop backends ANGLE usually maps mediump to the FULL native float, so the float path here runs at full precision while the int path runs at the int's exact ±215 — the two paths are not on equal precision footing, which is exactly the game's argument for the int pipeline.
  • ES 1.00 has NO integer modulo, abs, or min/max overloads. The game's compiled shader uses the float mod() + int() cast and the manual if (x < 0) x = -x; branch (what the sh2glsl generator emits) — the benchmark replicates those exact forms, so the int path's "integer" work is measured including the ES-1.00-mandated emulation of the missing int ops.
  • Vertex vs fragment. The vertex shader runs once per vertex (the grid mesh: mesh² vertices) and must be highp float; the fragment runs once per pixel (512×384) at mediump. The fragment ratio is the per-pixel ALU cost; the vertex ratio is the per-vertex transform cost (the yaw rotation + the fake perspective, the game's vertex workload) — both matter differently: the fragment cost scales with the screen area, the vertex cost with the geometry density.
  • WebGL1 / GLSL ES 1.00 only — no WebGL2, no intBitsToFloat, no explicit control-flow guarantees. The results are translator/driver-dependent by design; the GL info line tells you which translator produced them.
