GLSL ES 1.00 — int vs float fragment math benchmark

The mimecroft game's fragment shader does its colour math in mediump int (0..127 scale — the tint/scanline/corruption/vignette/crack intermediates all fit mediump int's ±215). This page renders the SAME per-fragment workload twice — once with the game's int pipeline, once with an equivalent float pipeline — and times each on your GPU. This measures whether the int arithmetic costs anything at all.

What the shaders do (the workload)

Both fragment shaders perform the same per-pixel work, on a fullscreen quad sampling a 64×64 (configurable) texture with REPEAT wrapping:

  1. tint — texture texel × the varying block colour (int: 0..127 scale with /128; float: 0..1)
  2. CRT scanline — every 6th pixel row dims 10%
  3. corruption — a deterministic hash of the pixel position (×7 + ×13 mod 97) throws 1 in 97 pixels to red
  4. vignette — corners darken toward the frame edge
  5. crack blend — a second texture (the crack overlay) mixed in by a damage level (int: mix = damage·cr_a capped at 127, /128; float: min(damage·cr_a,127)/127)

The two canvases show the visual result of each path — the int version has the 0..127 colour quantisation, the float version is smooth. They are otherwise visually identical, so the timing difference is the arithmetic itself.

The GLSL ES 1.00 implementation details (why this is meaningful)

  • Precision qualifiers are mandatory in ES 1.00. The vertex shader must declare precision highp float;; the fragment defaults to mediump. This benchmark uses exactly the game's declarations: mediump int / mediump float in the fragment, highp for the UV varying (so the texture coordinates don't quantise).
  • mediump int is ±215 (the ES 1.00 minimum). The game's int intermediates (r·tex_r ≤ 127·255 = 32385, the mix ≤ 127, the hash ≤ 96) all fit — the benchmark reproduces them exactly so the int path is legal on every ES 1.00 device.
  • mediump float has a ~10-bit mantissa — the float path's 0..1 arithmetic quantises the same way the game's 0..127 scale avoids. Both paths are "as the game would write them".
  • int() casts and mod()/floor() are real instructions. The int path pays int(gl_FragCoord.x), % 6, % 97 (integer modulo) and the /128 integer division; the float path pays mod() and min() instead. The benchmark measures the net ALU cost of that difference.
  • WebGL1 / GLSL ES 1.00 — the game's actual target (no WebGL2, no intBitsToFloat, no explicit control-flow guarantees). The results are driver-dependent — a desktop NVIDIA/AMD driver and a phone's Adreno/Mali will give different ratios.
